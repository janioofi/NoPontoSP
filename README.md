# NoPontoSP atualizado

Aplicativo Android Java/XML para consultar linhas, paradas, previsões e posições de ônibus de São Paulo. O nome exibido é **No Ponto SP** e o identificador do app é `com.janioofi.nopontosp`. Abra esta pasta no Android Studio. Consulte VALIDACAO.md para alterações, limitações e roteiro de testes.

Configure o SDK Android em local.properties. O token de desenvolvedor da API Olho Vivo é configurado dentro do app, pelo menu de configurações, e armazenado criptografado no dispositivo. A aparência pode seguir o sistema ou ser definida como clara/escura nas configurações; o mapa usa os tiles do OpenStreetMap em ambos os modos e aplica um filtro escuro localmente, sem exigir chave de outro provedor.

Linhas e paradas podem ser salvas pelos botões de favorito; os itens ficam no dispositivo e podem ser abertos pelo menu Favoritos. A tela Pontos próximos usa sua localização e o GTFS local para ordenar os pontos mais próximos. As novas telas **Horários** e **Itinerários** consultam `stops.txt`, `routes.txt`, `trips.txt`, `calendar.txt`, `stop_times.txt` e `frequencies.txt` locais: a primeira mostra passagens programadas no ponto selecionado no mapa, e a segunda permite consultar partidas por linha, dia, sentido e período. Esses horários são dados estáticos do GTFS, não previsões em tempo real. Como o conjunto incluído não contém `calendar_dates.txt`, o filtro de feriado usa a grade de domingo e não aplica exceções específicas. As buscas recentes aparecem como atalhos nas telas de busca. No mapa, toque em um ônibus para ver seus detalhes. Para receber um alerta de aproximação, abra o mapa por uma parada de uma linha e ative o alerta: ele consulta as posições online a cada 30 segundos e avisa quando um ônibus da linha estiver a até 500 metros; requer token da API e permissão de notificações.

Para compartilhar a versão de release, use `app/build/outputs/apk/release/app-release.apk`. A chave `app/no-pontosp-release-key.jks` e as propriedades de assinatura em `local.properties` são privadas, ficam fora do controle de versão e devem ser mantidas em backup seguro: são necessárias para publicar atualizações que possam ser instaladas sobre esta versão.

## Dados da SPTrans (GTFS e API Olho Vivo)

A SPTrans disponibiliza o GTFS e a API Olho Vivo para desenvolvedores. A documentação consultada descreve os serviços e o cadastro de aplicativos, mas não estabelece, por si só, uma licença explícita para republicar o conjunto de dados. A licença deste código não concede direitos sobre dados da SPTrans. Antes de redistribuir o GTFS ou seus derivados (inclusive arquivos `.json.gz`) em um fork, APK ou outro serviço, consulte os termos atuais de download e uso da SPTrans e confirme que a redistribuição é permitida. Na ausência de autorização clara, obtenha os dados diretamente da SPTrans e não os adicione ao repositório.

Para preparar os recursos localmente, baixe e extraia o GTFS oficial em uma pasta fora de `app/src/main/assets`, contendo `routes.txt`, `trips.txt`, `stops.txt`, `stop_times.txt`, `calendar.txt` e `shapes.txt` (ou `shapes1.txt`, `shapes2.txt` e `shapes3.txt`). `frequencies.txt` é opcional. Execute, na raiz do projeto:

```powershell
python tools\build_gtfs.py "C:\caminho\para\gtfs"
```

O gerador grava os recursos derivados em `app/src/main/assets/gtfs`: `index.json` relaciona linha, destino, sentido GTFS, viagem representativa e geometria; `<shape_id>.json.gz` armazena as coordenadas da rota; `stops_by_trip/<trip_id>.json.gz` guarda somente as paradas ordenadas daquela viagem/sentido; `stops/<shape_id>.json.gz` permanece como compatibilidade com recursos antigos; e as tabelas necessárias às telas de horários ficam em `tables/` como `routes.csv.gz`, `trips.csv.gz`, `stops.csv.gz`, `stop_times.csv.gz`, `calendar.csv.gz` e, quando fornecido, `frequencies.csv.gz`. Viagens circulares que começam e terminam no mesmo ponto e passam pelo destino indicado no letreiro são divididas em duas pernas, com geometrias e listas de paradas próprias para cada sentido. A separação das paradas por viagem evita misturar sentidos que compartilham um `shape_id`. A subpasta e a extensão distintas evitam conflitos do empacotador Android com os `.txt` GTFS originais. Depois de rodar o script, os `.txt` de origem podem ser removidos: o app lê as versões compactadas e também usa `tables/stops.csv.gz` em Pontos próximos. Para gerar em outra pasta sem modificar os recursos existentes, use `--output "C:\caminho\de\saida"`. Os recursos podem ser mantidos localmente para compilar e testar; só os publique depois de verificar os termos aplicáveis. Não inclua seu token pessoal da API Olho Vivo no código ou no repositório: cada pessoa deve configurar o próprio token no app.
